# 可失败验收条件

## 从模糊措辞改为可观察行为

| 模糊要求 | 可执行验收 |
|---|---|
| 支持保存快照 | 创建内容不同的 A、B 两份快照；刷新后两者仍在；恢复 A 后只出现 A 的内容，恢复 B 后出现新增内容 |
| 表单能提交 | 使用指定测试数据提交；页面显示成功；后台新增且仅新增一条匹配记录；重复点击不会生成意外重复记录 |
| 移动端适配 | 在约定宽度打开核心页面；无横向溢出、遮挡和不可点击控件；主要流程可完成 |
| 报表数字准确 | 按相同日期、退款和单位口径从明细重算；汇总差额为 0；保留计算式与数据源位置 |

## 每条用例的最小字段

- 唯一标识与对应需求。
- 前置条件和测试数据。
- 真实入口，不使用绕过用户路径的内部设置器。
- 操作步骤，包括刷新、重开、重复操作等关键状态变化。
- 可观察预期，包括界面结果和必要副作用。
- 能区分通过与失败的证据。
- 环境或权限不可用时的受阻条件。

## 正反样例

新增检查器时，先构造一个应通过的样例和一个含已知错误的样例。负样例必须因指定错误失败；若负样例也通过，应先修检查器，不能用它给产品背书。

## 人工复核边界

视觉美感、品牌一致性、叙事质量、观点合理性和节奏等可给出定位与建议，但保留人工复核。自动检查只对其能确定判断的属性给出通过或失败。
