# 独立 Review 协议

## 严重级别

| 级别 | 判定 |
|---|---|
| 阻塞 | 无法安全交付，存在数据破坏、严重安全或核心流程完全不可用 |
| 高 | 常见场景出现错误结果、权限绕过、明显需求缺失或严重回归 |
| 中 | 特定但合理触发条件下出错，或关键失败路径和测试覆盖不足 |
| 低 | 影响有限且可明确修复的问题；不是个人风格偏好 |

## 发现格式

```text
[级别] 简短标题 — path/to/file.ext:行号
触发：什么输入、状态或时序会出现。
影响：对用户、数据、权限或交付的具体影响。
依据：相关代码行为与需求条目。
验证：已运行的复现 / 静态推断及原因。
建议：最小修复方向和回归检查。
```

## 核验规则

- 先证伪自己的发现，检查调用方、保护条件和现有测试是否已经处理。
- 能安全复现时实际执行；不能复现时标记静态推断，不写成已发生事实。
- 将需求问题与代码问题分开，业务规则不清时请求决策。
- 将测试缺口单列，不把“没测试”自动夸大为代码缺陷。
- 发现无关既有问题时说明其超出本次差异，不混入本次改动责任。
- 没有发现时列出审查范围、实际运行检查和残余风险。
